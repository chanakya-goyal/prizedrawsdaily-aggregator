# Moving `draw-images` to Cloudflare R2

## Why

The Supabase Free plan meters two separate things, and this bucket was on course to
breach both:

| quota | state on 2026-09-19 |
|---|---|
| Egress, 5 GB/month | **breached** — 7.67 GB in the 20 Aug–20 Sep cycle |
| Storage size, 1 GB | **708.3 MB and +16.0 MB/day → full around 9 Oct** |
| Database size, 500 MB | 34 MB. Not a factor, and not what moves. |

Compression cannot buy the headroom. The draw hero is served at `w=1280`
(`draws.$slug.tsx:320`), so the stored 1280/q75 is already correctly sized — anything
smaller upscales the most important image on every draw page. Measured: re-encoding
to 960 would save 429 MB and visibly degrade that hero.

R2 includes 10 GB of storage and charges **nothing for egress at any volume**. At the
current 16 MB/day that is ~1.7 years of runway, and it removes Storage egress from the
Supabase meter entirely.

**The database stays on Supabase.** Only the bytes move, so every one of the ~177
PostgREST/auth call sites across both repos is untouched.

## What you have to do (I cannot do these)

1. **Cloudflare account** with R2 enabled, and **a payment method on file**. Without
   one, R2 suspends the bucket the moment the free allowance is used and requests
   start erroring. Usage at this scale should stay inside the free tier.
2. **Create the bucket**, e.g. `pdd-draw-images`.
3. **A custom domain for it.** `r2.dev` is rate-limited and Cloudflare documents it as
   not for production. `prizedrawsdaily.co.uk` is on GoDaddy nameservers today, so
   this means adding the zone to Cloudflare — a full nameserver move, or a partial
   (CNAME) setup for just `img.prizedrawsdaily.co.uk`.
   Keep **Bot Fight Mode off** for that hostname: images.weserv.nl fetches every image
   server-side and a bot challenge would break every image on the site.
4. **An R2 API token** (Object Read & Write) for that bucket.

## Then set these

```sh
IMAGE_PROVIDER=r2
R2_ACCOUNT_ID=...
R2_BUCKET=pdd-draw-images
R2_ACCESS_KEY_ID=...
R2_SECRET_ACCESS_KEY=...
R2_PUBLIC_BASE=https://img.prizedrawsdaily.co.uk/
```

They belong in **four** places, and the fourth is the one that broke the August move:

| where | why |
|---|---|
| `~/pdd-aggregator/.env` | local runs |
| GitHub secrets on `prizedrawsdaily-aggregator` | `aggregate.yml` (`0 7 * * *`) and `aggregate-json.yml` (`0 1,13,19 * * *`) |
| Vercel env (site) | only if the site ever writes images — `src/lib/import.functions.ts` does |
| **the scheduled Claude cowork routine** | it holds its OWN copy of the credentials, in no repo and no `.env`. Documented at `COWORK.txt:53-54` and `manager/PROMPT.md:6`. Forget it and the scraper keeps writing to the old place, silently. |

## Running it

Three phases, deliberately separate. `DRY_RUN=true` is the default for all of them.

```sh
bun migrate-to-r2.mjs --phase=copy                  # dry run: what would copy
DRY_RUN=false bun migrate-to-r2.mjs --phase=copy    # Supabase → R2. Resumable.
bun migrate-to-r2.mjs --phase=verify                # exits non-zero unless every
                                                    # referenced object is present,
                                                    # right-sized and cacheable
DRY_RUN=false bun migrate-to-r2.mjs --phase=rewrite # repoint draws.image_url +
                                                    # operators.logo_url
```

`--limit=N` on any phase to rehearse on a handful first. Start there.

**Do not skip `verify`.** `rewrite` only repoints a row whose object it can stat on R2,
but `verify` is what proves the whole set landed before you touch a single row.

## Safety properties

- **Nothing is ever deleted.** The Supabase objects remain as the rollback copy.
  Reclaiming that 708 MB is a separate, later decision.
- **`copy` is idempotent and resumable** — an object already on R2 at the right size is
  skipped, so an interrupted run only costs what it had not reached.
- **A truncated download can never land**: bytes are compared against the source's
  recorded size before writing.
- **Dead-project rows are skipped, not copied.** ~390 ended draws still point at
  `kkuuwksgyypicnblwubs`, which is already 402. That is `repair-images.mjs`'s problem.
- **Cache-control is set on every write** — `public, max-age=31536000`, the same header
  whose absence turned a 596 MB bucket into 6.37 GB of egress. `verify` re-checks it
  over the public URL with **GET**, because HEAD lied on Supabase Storage.
- **`prune-orphans.mjs` cannot eat the rollback copy.** `referencedPaths` now resolves
  URLs against every base we own, and the script's existing `MIN_REF_RATIO` breaker
  aborts if under 50% of objects look referenced.

## Rollback

The Supabase bytes are still there and still public. Repoint the rows back to
`https://<ref>.supabase.co/storage/v1/object/public/draw-images/<path>`, unset
`IMAGE_PROVIDER`, and nothing else has changed.
